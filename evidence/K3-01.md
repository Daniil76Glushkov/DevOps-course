# K3-01. CI/CD и ветки

## Схема

```text
короткая ветка kt3
        │
        ▼
PR в main своей копии
        │
        ▼
Student CI: test ──успех──► build
        │
        ▼
решение о слиянии в main
```

В этой работе CI автоматически запускает тесты на `push` и
`pull_request`. Сборка Docker-образа выполняется только после успешного
теста. Отдельное решение о выпуске остаётся за человеком: Student CI не
публикует образ и не разворачивает его.

Для небольшой учебной работы выбрана короткая ветка и PR в `main`: ошибка
встречается с общим кодом уже при проверке PR, а автор получает обратную
связь до слияния. Git-flow с долгоживущими `develop`/`release` и
дополнительными ветками полезен для сложных релизных процессов, но здесь
добавляет переходы и задерживает обратную связь.

CI — автоматические проверки изменений; Continuous Delivery — подготовка
изменения к управляемому выпуску; Continuous Deployment — автоматический
выпуск каждого изменения, прошедшего условия. В данной КТ сделана только
часть CI: `test` и сборка образа.
